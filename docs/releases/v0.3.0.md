# Ei Void 0.3.0 — production UI preview

This release is a full UI pass on the assistant-first app. The product surface
is now a deliberate OLED interface built around the chalk-cat mark, not a
debug shell with placeholder chrome.

## What changed

- **No debug ribbon.** The yellow Clerk-bypass banner is gone from every screen.
  System bars are black with light icons on the OLED canvas.
- **Inter typography.** Regular, Medium, SemiBold and Bold are bundled, so the
  layout is identical across phones and no longer depends on the OEM font.
- **Assistant home.** Branded header, short greeting, four capability cards
  with line icons and descriptions, a workspace card for reminders and
  projects, a privacy line and a floating composer.
- **Drawer.** Brand header, account card, a primary New chat action, grouped
  Workspace and Preferences sections, selected-state treatment, and a layout
  that scrolls on short landscape screens.
- **Composer.** Plus menu with line icons, dictation, and a blue voice action
  that becomes a send arrow when text is present.
- **Chat and errors.** Refined bubbles, assistant mark, streaming dots, and a
  clear provider-key error with a direct Customize action.
- **Icons.** Every structural action uses a vector icon; the old emoji task
  chips are gone.

The Discord notification link, reminders, projects, provider keys, usage and
website from 0.2.0 are unchanged.

## Install

Download `EiVoid-v0.3.0-debug.apk`. It targets Android 13 (API 33) and newer,
arm64.

The preview is **debug-signed** because release signing secrets are not
configured on the repository. It still opens the local workspace so the UI can
be reviewed without Clerk credentials. Configure the four
`ANDROID_KEYSTORE_*` / `ANDROID_STORE_PASSWORD` secrets for a signed production
build.

## Not live yet

- No hosted API, PostgreSQL database or Render deployment is included.
- Clerk, Discord and AI-provider credentials are not committed.
- App-to-dashboard usage sync is not enabled yet.
